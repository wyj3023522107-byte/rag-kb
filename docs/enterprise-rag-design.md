# 企业级 RAG 系统设计方案

## 一、当前问题分析

### 1.1 切分问题
- **问题**: 只用固定字符数切分，不考虑文档结构和语义边界
- **后果**: 切片可能截断重要信息，召回的上下文不完整

### 1.2 召回问题
- **问题**: 向量检索 + BM25 的简单混合，没有查询优化
- **后果**: 召回不精准，漏召回或误召回

### 1.3 排序问题
- **问题**: LLM 打分只看前 200 字符，效率低且不准
- **后果**: 排序结果不可靠

### 1.4 元数据问题
- **问题**: 切片元数据只有索引信息，缺少语义信息
- **后果**: 无法进行精细化过滤和多维度召回

#### 3.1.3 语义切分 (Chunking) - 核心改进
```python
class SemanticChunker:
    """语义感知的文档切分器"""

    切分策略:
    1. 结构优先切分
       - 按标题层级切分
       - 保持段落完整性
       - 表格/代码块不切分

    2. 语义边界切分
       - 使用 embedding 计算相邻段落相似度
       - 在语义突变处切分
       - 阈值: 相似度 < 0.5

    3. 多粒度切分
       - 细粒度: 200-300 tokens (精确召回)
       - 中粒度: 500-800 tokens (平衡)
       - 粗粒度: 1000-1500 tokens (上下文完整)

    4. 滑动窗口切分
       - 重叠窗口保持上下文连贯
       - 窗口大小: 可配置
       - 步长: 窗口大小 * 0.3
```

```python
class VectorIndex:
```

### 3.3 检索层 (Retrieval)

#### 3.3.1 查询理解 (Query Understanding)
```python
class QueryUnderstanding:
    """查询理解"""

    1. 意图识别:
       - 事实查询: "勾股定理是什么"
       - 对比查询: "A和B的区别"
       - 步骤查询: "如何计算..."
       - 定义查询: "什么是..."

    2. 实体抽取:
       - 学科: 数学、物理
       - 年级: 初二、高三
       - 知识点: 勾股定理、牛顿定律
       - 专有名词: 人名、地名

    3. 查询扩展:
       - 同义词扩展: "函数" -> "方法", "映射"
       - 上下位扩展: "动物" -> "哺乳动物"
       - 相关词扩展: "勾股定理" -> "直角三角形", "斜边"

    4. 查询改写:
       - 纠错: "勾古定理" -> "勾股定理"
       - 规范化: "咋算面积" -> "如何计算面积"
       - 补全: "它" -> 替换为上文实体
```

#### 3.3.2 多路召回 (Multi-way Recall)
```python
class MultiWayRetriever:
    """多路召回策略"""

    召回路径:

    1. 向量召回:
       - 语义相似度匹配
       - top_k: 20-50

    2. 关键词召回:
       - BM25 精确匹配
       - SPLADE 扩展匹配
       - top_k: 20-50

    3. 图谱召回:
       - 实体关联召回
       - 多跳推理召回
       - top_k: 10-20

    4. 摘要召回:
       - 快速匹配摘要
       - 再召回原文
       - top_k: 20

    5. 问题召回:
       - 匹配预生成的问题
       - 召回对应切片
       - top_k: 10

    召回策略选择:
    - 简单查询: 向量 + 关键词
    - 实体查询: 向量 + 图谱
    - 复杂查询: 全路召回
```

#### 3.3.3 智能融合 (Fusion)
```python
class FusionStrategy:
    """融合策略"""

    1. RRF (Reciprocal Rank Fusion):
       score = Σ 1/(k + rank_i)

    2. 权重融合:
       score = α * vector_score + β * keyword_score + γ * kg_score

    3. 自适应权重:
       - 根据查询类型动态调整权重
       - 事实查询: 向量权重高
       - 精确查询: 关键词权重高

    4. 去重合并:
       - 相似切片合并
       - 保留最高分
```

```python
class Reranker:
    """精排 - 重排序模型"""

    模型选择:
    1. 专用 Rerank 模型:
       - bge-reranker-large (中文)
       - cross-encoder/ms-marco

    2. LLM Rerank:
       - Pointwise: 单个文档打分
       - Listwise: 多个文档排序
       - Pairwise: 两两比较

    特征融合:
    - 语义特征: 相似度
    - 相关性特征: 关键词覆盖
    - 质量特征: 文档质量分
    - 新鲜度: 文档时间
```

#### 3.4.3 多样性优化
```python
class DiversityOptimizer:
    """多样性优化"""

    MMR (Maximal Marginal Relevance):
    score = λ * relevance - (1-λ) * max_similarity_to_selected

    目的:
    - 避免返回高度相似的结果
    - 覆盖多个相关子主题
```

### 3.5 生成层 (Generation)

#### 3.5.1 上下文构建
```python
class ContextBuilder:
    """上下文构建"""

    策略:

    1. 窗口上下文:
       - 召回切片的前后切片
       - 保持上下文完整性

       - 同一文档的其他相关切片
       - 引用/被引用关系

    3. 上下文压缩:
       - LLM 压缩无关信息
       - 保留核心信息

    4. 上下文排序:
       - 相关性高的在前
       - 或按原文顺序
```

```python
class AnswerVerifier:

    2. 一致性: 答案是否与上下文一致
    3. 完整性: 答案是否完整
    4. 准确性: 事实是否正确
```

```yaml
  min_chunk_size: 200
  max_chunk_size: 800

  questions: true
  entities: true

  vector:
    model: "BAAI/bge-m3"
    dimension: 1024
  keyword:
    tokenizer: "hanlp"
    stopwords: true
  graph:
    enabled: true

retrieval:
  query_understanding:
    intent: true
    entity: true
    expansion: true
  multi_recall:
    vector_weight: 0.5
    keyword_weight: 0.3
    graph_weight: 0.2
  rerank:
    model: "BAAI/bge-reranker-large"
    top_k: 5

generation:
  context_window: 3  # 前后各 3 个切片
  max_context_length: 4000
  citation: true
```
